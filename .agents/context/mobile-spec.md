# 移动端适配规范 v1（7 个游戏的统一验收口径）

> 容器层共享约定，2026-11-18 用户裁决：**触屏操控 + 响应式 HUD + 竖屏可玩**，
> 并用 375×812 竖屏、844×390 横屏逐个截图验收、控制台零报错。
> 各游戏在自己的仓库里落地，本文件只管「什么叫合格」。

## 目标设备

| 档位 | 视口（CSS px） | 定位 |
| --- | --- | --- |
| 竖屏主档 | 375×812（iPhone SE/13 mini 起） | **必须完整可玩一局** |
| 横屏 | 844×390 | 必须可玩，布局不能崩 |
| 桌面回归 | 1440×900 | 不能比现在更差（鼠标键盘全部照旧） |

## 一、触屏输入（必做）

1. **纯触摸必须能完成一局**：不许出现「只能键盘才能玩」的功能缺口。
   暂停/继续/重开/静音这些跨越全部游戏的操作，必须在触屏上有入口。
2. 事件用 **Pointer Events**（`pointerdown/pointermove/pointerup/pointercancel`），
   不要只绑 `mouse*`；已有 `pointerdown` 的不必改成 `touchstart`。
3. 可点元素最小 **44×44 CSS px**（含 HUD 图标按钮；HUD 空间实在紧时下限 40×40）。
4. 触摸目标之间至少 8px 间距，避免误触。
5. 画布/摇杆区域必须 `touch-action: none`，否则页面的滚动/缩放会把操作吃掉。
6. 多点触控（同时移动 + 射击/瞄准）用 `pointerId` 区分，不要用「最后一个触摸」覆盖前一个。

## 二、布局

1. **不允许横向滚动**：`document.scrollingElement.scrollWidth <= innerWidth + 1`。
2. 用 `100dvh`（不用 `100vh`），并配 `env(safe-area-inset-*)` 处理刘海与底部横条。
3. 字号：正文/HUD ≥ 12px，主数值（分数、波次）≥ 16px；面板内边距在窄屏收到 12～16px。
4. 面板类 UI（菜单、结算、侧栏）在竖屏下改为纵向或抽屉/底部横条，
   且内容超出时可滚动（`overflow:auto` + `-webkit-overflow-scrolling`），不能把内容裁掉。
5. 竖屏与横屏都要显式处理；横屏可用 `@media (orientation: landscape)` 收紧纵向间距。

## 三、不让桌面退化

- 原有键盘/鼠标全部保留，`pointer` 事件同时服务鼠标与触摸。
- 桌面视口的截图不得出现明显错位（用 1440×900 复核一次）。

## 四、性能与手感底线

- 拖动/摇杆的 `pointermove` 里不写 `preventDefault` 之外的同步布局测量；
- 触摸后不要触发 300ms 点击延迟以外的整页滚动（`touch-action` 已覆盖）；
- 不新增任何外部资源（CDN、字体、图片），沿用各游戏既有的「零外部依赖」约束。

## 五、验收（工具化，不靠肉眼）

容器根有 `node .agents/work/tools/mobile-check.mjs`，对每个游戏：

```bash
# 竖屏 375×812 + 横屏 844×390，各截一张图并收集 console 报错
node .agents/work/tools/mobile-check.mjs --name snake --dir "3D经典贪吃蛇"
```

判据（工具自动算，任一不过即不合格）：

1. `errors` 为 0（console error / exception）；
2. `overflowX` 为 0（无横向滚动）；
3. `canvas` 存在且未被 UI 完全遮挡（canvas 可见面积 > 20%）；
4. 竖屏与横屏截图目视无重叠、无出血、无不完整面板。

## 六、记录

每个游戏在自己的 `.agents/context/current-state.md` 追加一节，写清：

- 加了哪些触屏入口（摇杆/滑动/按钮/长按…），各自怎么触发；
- 响应式断点与竖屏/横屏布局取舍；
- 验证结论（测试条数、截图文件名、桌面回归结论）；
- 已知不足（例如「双指缩放没做」）。

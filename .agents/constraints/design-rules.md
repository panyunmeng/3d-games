# 设计硬约束

改代码前先读这一页。这里不是风格偏好，是改动会直接破坏某个事实的边界。

## 1. 规则与渲染彻底解耦

规则只存在于 `src/sokoban.ts`（格子索引 + 位图占用），`scene.ts` 只读状态、写位置，不得参与合法性判定。
理由：判定错了是玩法错误，渲染错了只是看起来别扭；两者混在一起就无法单独验证。加新玩法（冰面、传送点）时先改引擎，再加渲染。

## 2. 一步的时序只有一个来源

`main.ts` 的 `tick()` 按 `MOVE_MS` 节奏从队列取方向。键盘和点击只往队列塞方向。
不要在各处直接调 `game.move()` 再自己插值——否则连按会丢步、撤销会和动画打架。

## 3. 像素风靠采样点少，不靠后期滤镜

- 画布按 `PIXEL_SCALE=3` 缩小渲染，`setSize(w/3, h/3, false)` + CSS 拉满 + `image-rendering: pixelated`。
- 纹理一律 32×32、`NearestFilter`、`generateMipmaps=false`。
- 不要加抗锯齿、模糊、发光后期；需要「好看」就在纹理和配色上解决。

## 4. 贴图全部代码生成

`textures.ts` 用 Canvas 画，固定种子伪随机（`mulberry32`），保证每次打开一致。
仓库里不允许出现 .png/.jpg/.glb 之类美术资源；要换风格就改绘制函数。

## 5. 场景图的生命周期

换关时 `clearLevel()` 会 dispose 几何体与**非共享**材质。共享材质登记在 `sharedMats`，漏登记的材质会被下一关释放掉。
新增共享材质必须 `this.sharedMats.add(mat)`。

## 6. 点击拾取必须包含墙

`pickCell()` 的射线列表里有墙，命中墙返回 null。少了这一步，点墙会选中墙背后的地板，玩家会莫名走错。

## 7. 关卡数据不许手改

`src/levels.ts` 由 `scripts/gen-levels.mjs` 从 `assets/Microban.txt` 生成。
作者声明关卡集可自由分发但须保留署名：页面左下角与 `levels.ts` 头部都保留了 David W. Skinner 的信息，删它是违约。

## 8. 关卡合法性由数据保证

`parseLevel()` 会洪泛 `inside` 并要求玩家存在；如果关卡边界有漏口，玩家能走进虚空。
新增关卡集时先跑一遍：箱子数 == 目标点数、玩家存在、内部区域不触边界。

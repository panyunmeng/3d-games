# 交付硬约束

改这个项目之前先读完。这些都是从事实推导出来的，不是习惯。

## 1. 单文件交付

- 交付物只有 `index.html` 一个文件，且**只能由 `python build.py` 生成**。
  手改 `index.html` 会在下次构建时被覆盖，且破坏「源码即事实」。
- 构建链：`src/shell.html` + `src/game.js` + `vendor/three.min.js` → `index.html`。
- 验证链：`node --check src/game.js` → `python build.py` → 用 `?selftest=1` 读断言。

## 2. 运行时零外部依赖

- 不允许 CDN、外链字体、外链图片、外链音频。当前音效全部由 WebAudio 合成，
  图标由 canvas 现画，Three.js 内联在文件里。
- 理由：交付方式是「拷贝一个 HTML 双击打开」，任何外部依赖都会在断网/内网环境下直接失效。

## 3. 不用 ES module

- `file://` 下 `<script type="module">` 被 CORS 拦截，页面直接白屏。
  新增库必须是经典 `<script>`（UMD），这也是选 Three.js r149 而不用新版 `three.module.js` 的原因。
- 升级 Three.js 时要重新确认：还有 UMD 构建、且 `ColorManagement.legacyMode` 语义未变。

## 4. 物理不变式（改动必须保持）

- 玩法平面是 XZ；碰撞只在 XZ 做 圆-AABB，球心 Y 固定。不要引入 Y 方向运动。
- 固定步长 `1/120 s`；单步位移不超过 `0.6 × 球半径`（防隧穿）；
  反弹后强制 `|dz| >= 0.32`（防贴墙横飞死局）。
- 球用「单位方向 + 标量速度」，不要退回 `vx/vz` 存速度（否则变速时会改坏朝向）。
- 任何物理/关卡改动必须让 `?selftest=1` 全绿（16 条断言：无 NaN、不越界、不穿砖、
  击碎数、计分、多球上限、加宽生效/还原、接道具、命耗尽、过关生成）。
- 后台标签页 rAF 被节流到几 Hz，手工点击**不能**用来判断球速与碰撞是否正确。

## 5. 色彩与光照

- `THREE.ColorManagement.legacyMode = false` 是刻意的：r149 默认 legacy 会让 hex 颜色
  不转线性却在输出端 sRGB 编码，整画面被抬亮一档，霓虹配色会被冲成粉彩。
- 觉得画面过曝/过暗时，先查色彩管线与材质自发光，不要靠加灯亮度硬补。

## 6. 关卡与血量表达

- 关卡是数据：每行一个 10 字符模式（`#` 1 血、`@` 2 血、`%` 3 血、`.` 空），
  行号 0 离玩家最近。加关卡优先加数据，不要加分支逻辑。
- 血量用砖块正面的装甲亮带表达（2 血 1 条、3 血 2 条）。
  已否决的方案：用高度表达血量——35° 俯视下更高的前排会把后排整排挡掉，可读性反而更差。

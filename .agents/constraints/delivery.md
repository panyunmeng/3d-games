# 交付硬约束

改动前先过一遍。任何一条不满足，产物就不算完成。

## 1. 单文件、双击即玩

- 交付物只有一个 `index.html`，双击在 `file://` 下能玩，不需要服务器、不需要联网、不需要 npm
- 因此：不能用 `type="module"`（`file://` 下被 CORS 拦）、不能引 CDN/外链字体/图片
- `index.html` 只能由 `python build.py` 生成，禁止手改；改完 `src/` 必须重建

## 2. 判定与渲染分离

- 规则（形状、旋转、踢墙、消行、计分、等级、随机）只能写在 `src/core.js`
- `core.js` 不许出现 DOM / WebGL / `THREE` / `window` 依赖；必须能 `require()` 进 node 跑单测
- 渲染层只能读内核状态，不能自己算规则；否则单测覆盖不到，浏览器和测试会各说各话

## 3. 判定平面是 2D，渲染才是 3D

- 消行判定严格在 10×20 网格上；相机旋转、透视、立体渲染都不参与判定
- 相机拖动只改观感。任何「看起来能落但判不到」或反过来的情况都是 bug
- 幽灵落点必须由内核 `ghostY()` 给出，渲染层不得自己预测

## 4. 颜色管理必须打开

`three` r149 默认 `ColorManagement.legacyMode = true`：材质颜色不做 sRGB→线性转换，
输出端却做线性→sRGB，等于把每个颜色提亮约 2 倍。不打开正确颜色管理，
无论怎么调灯光都会得到粉彩色。当前在 `game.js` 顶部显式打开 `enabled` / 关掉 `legacyMode`。

## 5. 帧率与开销

- 目标：满帧（实测 120 fps @ 120 Hz 显示器）
- 屏幕上的方块网格用**对象池**（最多 200 个 mesh），只在锁定/消行时刷新可见性，不每帧重建
- 禁止每帧 `new THREE.Color` / `new Geometry` / 重建材质；循环内只用预分配对象

## 6. 验证标准

- `npm run check` 全绿（语法 + 25 条内核单测）
- `?selftest=1` 6/6 通过，且控制台无 error
- 新增规则必须有对应的 node 断言；新增视觉必须能用 `?demo=1` 或 `?scenario=` 复现
- 只有「人工点着玩着没问题」不算验证

## 7. 音频

- 全部用 WebAudio 实时合成，不引入音频文件
- `AudioContext` 必须等真实用户手势后才创建（否则控制台会刷 autoplay 警告）
- 静音状态持久化到 `localStorage`

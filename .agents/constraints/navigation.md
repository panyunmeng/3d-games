# 容器层的行为约束

> 2026-11-19 结构变更：本文原第 1 条是「不在根目录建 git」，现在反过来——
> 根目录**就是**仓库。原文保留在文末，说明当时为什么那样定，以及为什么改。

## 1. 根目录是仓库，提交要覆盖全部受影响目录

`3D游戏合集/` 现在是单一 git 仓库。改多个目录时，**一次提交覆盖多处**是正常
且期望的做法（合并前做不到，得跨 8 个仓库各提交一次，这正是合并的原因）。

提交信息里写清改了哪几个目录。仍然用中文 + emoji + Conventional Commits。

## 2. 不在根目录放交付物或过程文件

根目录只允许：8 个子目录 + `AGENTS.md` + `README.md` + `LICENSE` +
`.gitignore` + `.agents/`。

新文件先问：它属于哪个项目？归平台就放平台，归游戏就放游戏。
两边都不属于，说明它是过程文件，放 `.agents/work/`（已 gitignore）。

## 3. 权威在子目录，不在本层

本层的 `AGENTS.md` 只做导航。任何技术细节（命令、踩坑、部署参数）
写进对应子目录；本层不复制，避免两份事实各改各的。

## 4. 改游戏后必须回平台重建

源码与线上是两个实例。改了游戏代码不重跑平台构建，线上就还是旧的。
完整链条见根 `AGENTS.md`。

## 5. 两个远端，可见性不同

- `origin` = Gitea 私有（主仓库）
- `github` = GitHub 公开

推 GitHub 前必须先确认没有内部信息（NAS 路径、内网 IP、口令载体路径）。
细节见 `git-remotes.md`。

## 附：原文保留（2026-11-19 之前）

### 原 1. 不在根目录建 git

根目录 `3D游戏合集/` 是容器，不是仓库。不要在这里 `git init`。

**当时的理由**：8 个子目录各有完整 `.git`。在根建仓库它们会变成嵌套仓库
（或被当作 submodule），`git status` 会变得无法阅读，且没人能说清
「根仓库到底管什么」。

**为什么改**：那个理由成立的唯一前提是「子目录保留自己的 .git」。
合并时用 `git subtree add` 把内容并入根仓库后，子目录里已经**没有** `.git` 了，
嵌套仓库的问题不存在。反过来，8 个仓库带来的跨仓库提交成本是每天都要付的。

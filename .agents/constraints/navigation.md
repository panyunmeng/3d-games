# 容器层的行为约束

## 1. 不在根目录建 git

根目录 `3D游戏合集/` 是容器，不是仓库。不要在这里 `git init`。

**理由**：8 个子目录各有完整 `.git`。在根建仓库它们会变成嵌套仓库
（或被当作 submodule），`git status` 会变得无法阅读，且没人能说清
「根仓库到底管什么」。

## 2. 不在根目录放交付物或过程文件

根目录只允许：8 个子目录 + `AGENTS.md` + `.agents/`。

新文件先问：它属于哪个仓库？归平台就放平台，归游戏就放游戏。
两边都不属于，说明它是过程文件，放对应仓库的 `.agents/work/`。

## 3. 权威在子目录，不在本层

本层的 `AGENTS.md` 只做导航。任何技术细节（命令、踩坑、部署参数）
写进对应子仓库；本层不复制，避免两份事实各改各的。

## 4. 改游戏后必须回平台重建

游戏仓库与线上是两个实例。改了游戏代码不重跑平台构建，线上就还是旧的。
完整链条见根 `AGENTS.md`。

# 统一设计语言规范 v1

> 7 个游戏共有的一套规则。**改任何视觉或键位之前先读这里**，
> 新增游戏也必须符合本规范，否则平台的门户与它会看起来像两家产品。

## 为什么需要它

7 个游戏是独立开发的，实测差异如下（2026-11-17 快照）：

| 维度 | 当时的实际情况 |
| --- | --- |
| 字体 | 3 种写法：`PingFang SC/微软雅黑`、`-apple-system`、`ui-monospace` |
| 背景色 | 7 个全不同：`#070a14` `#0a0618` `#020308` `#0b0907` `#0d0f14` `#05070c` `#0b0e12` |
| 圆角 | 4～28px 不等，同一游戏内也不一致 |
| 文案 | 「重开」vs「重新开始」、「静音」vs「音效」、「暂停」vs「Pause」 |
| 键位 | P/Esc 都能暂停，R 都能重开，但 M 静音只在部分游戏有 |

这些差异单独看都不算错，放在一个门户里就是「七个不同产品」。

## 一、设计令牌（Design Tokens）

### 字体

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif;
--font-mono: ui-monospace, "Cascadia Mono", Consolas, "Microsoft YaHei", monospace;
```

- **界面文字一律用 `--font-sans`**，包括 HUD、按钮、弹窗、标题。
- `--font-mono` 只用于**数字读数**（分数、计时、步数）——等宽让跳动不抖。
- 禁止再出现第三种字体栈。推箱子当前整体用等宽字体，是唯一的例外来源，
  它的像素风需要等宽感，但**界面文案（按钮、菜单）仍应改回 sans**。

### 色彩

深色底是共同基调，统一背景层，**保留各游戏自己的强调色**（这是它们的个性）：

```css
/* 所有游戏共用 */
--bg:        #0a0d16;   /* 统一底色，比原来 7 个的中位数再深一点 */
--panel:     rgba(16, 21, 34, 0.88);
--panel-2:   rgba(24, 31, 48, 0.92);
--line:      rgba(140, 165, 210, 0.16);
--line-soft: rgba(140, 165, 210, 0.09);
--text:      #e8edf7;
--muted:     #93a0b8;
--dim:       #64708a;

/* 语义色，含义固定，不随游戏变 */
--ok:        #5fd08a;
--warn:      #e8a33a;
--danger:    #e05a4f;
```

各游戏的**强调色**（`--accent` / `--accent-2`）保留，用于：

- 主按钮、选中态、进度条、当前关卡高亮
- 不允许用它改背景、正文颜色

| 游戏 | --accent | --accent-2 |
| --- | --- | --- |
| 贪吃蛇 | `#6cf0a8` | `#6ad9ff` |
| 俄罗斯方块 | `#7aa2ff` | `#ffd166` |
| 打砖块 | `#4fc7ff` | `#63f2b6` |
| 扫雷 | `#c8863c` | `#e8b06a` |
| 推箱子 | `#e3a636` | `#5fd08a` |
| 塔防 | `#36d2ff` | `#ffc247` |
| 坦克大战 | `#7ac043` | `#f5c542` |

### 尺寸与圆角

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--radius-sm` | 8px | 小徽标、tag、按键提示 |
| `--radius` | 12px | 按钮、输入框、卡片 |
| `--radius-lg` | 18px | 面板、弹窗、菜单容器 |
| `--gap-1` | 6px | 图标与文字 |
| `--gap-2` | 12px | 控件之间 |
| `--gap-3` | 20px | 区块之间 |
| `--gap-4` | 32px | 页面级的边距 |

圆角只用这四档，不再出现 14/16/20/22/26/28px 这类中间值。

## 二、键位（统一，不可各写各的）

| 功能 | 键 | 说明 |
| --- | --- | --- |
| 暂停 / 继续 | `Esc` **和** `P` | 两个都接受，`Esc` 是首选 |
| 重开本局 | `R` | 一律重开当前局，不弹确认框 |
| 静音开关 | `M` | 状态持久化到 localStorage。**仅限有音频的游戏**，见下 |
| 确认 / 开始 | `Enter` 或 `空格` | 菜单态下 |

**各游戏自己的操作键**（移动、射击、旋转等）保持原样，不统一——那是玩法。

对于**没有键盘输入的**（扫雷目前纯鼠标），必须补上 `Esc`/`P` 暂停、`R` 重开；
有音频的再加 `M` 静音，否则在合集里只有它一个不能用键盘。

### 条件条款：M 静音取决于「有没有音频」

`M` 不是无条件要求。判据是**该游戏有没有可静音的对象**：

| 情况 | 做法 |
| --- | --- |
| 有音效 / 音乐 | 必须有 `M`，且状态持久化到 localStorage |
| 完全无音频 | **不加 `M`**，并在该游戏台账登记「无音频」 |

为什么无音频不加：控件必须有可观察效果。一个按下去什么都不变的键，
比没有这个键更糟——玩家会以为坏了。这不是「暂时不做」，而是「现阶段
没有可作用的对象」。

将来该游戏补上音频子系统时，`M` 就是既有规范要求，不需要重新讨论。
已登记的无音频游戏：**3D推箱子**（2026-11-17 核实，零 AudioContext/振荡器/音频资源）。

## 三、文案（逐字统一）

| 场景 | 用词 | 不用 |
| --- | --- | --- |
| 恢复游戏 | **继续** | 恢复、Resume |
| 重新开始当前局 | **重开** | 重新开始、重玩、Restart |
| 关闭声音 | **静音** | 音效、关闭音效、Mute |
| 打开声音 | **取消静音** | 开音效、开启声音 |
| 开始游戏 | **开始游戏** | 开始战役、进入游戏、Start |
| 音效总开关（设置项） | **音效** | 声音、SFX |
| 背景音乐（设置项） | **音乐** | BGM、背景音 |

注意区分：**按钮上用动作**（静音 / 取消静音），**设置项用名词**（音效 / 音乐）。

## 四、HUD 布局约定

统一位置，避免每个游戏都往左上角堆东西：

```text
┌──────────────────────────────────────────────────────┐
│ 左上：游戏名 / 模式徽标                               │
│ 顶部中间：主数值（分数 / 步数 / 波次），用 mono 字体   │
│ 右上：次要操作（暂停 / 静音 / 重开 的小图标）          │
│                                                       │
│                     游戏画面                          │
│                                                       │
│ 左下：操作提示（可折叠）    右下：返回平台（平台注入） │
└──────────────────────────────────────────────────────┘
```

- **右下角留给平台**：平台注入的「← 返回平台」固定占右下 12px，
  各游戏不要往那里放控件（塔防的倍速按钮目前就在右下，需要挪）。
- 返回按钮的样式由平台注入，游戏不感知、不覆盖。

## 五、按钮形态

三档，只用这三档：

| 档位 | 用途 | 样式 |
| --- | --- | --- |
| 主按钮 | 开始游戏、确认 | `--accent` 实底 + 深色文字，圆角 `--radius` |
| 次按钮 | 继续、设置、取消 | 透明底 + `--line` 边框 + `--text` |
| 图标按钮 | 暂停、静音、重开 | 32×32，圆角 `--radius-sm`，无边框，hover 显底色 |

禁用态统一：`opacity: .4` + `cursor: not-allowed`，不改颜色。

## 六、动效

- 过渡时长 `180ms`，缓动 `ease`
- 只动 `transform` / `opacity`，不动 `width` / `height` / `top` / `left`
- 尊重 `prefers-reduced-motion: reduce`：关闭所有非必要动效

### 各游戏的构建形态不同，别想当然

改完怎么验证取决于它的交付形态，`games.manifest.mjs` 里 `kind` 字段是权威：

| kind | 游戏 | 改完要做什么 |
| --- | --- | --- |
| `static` | 贪吃蛇、扫雷 | **零构建**，改完直接生效，只需 `node --check` 语法自查 |
| `single` | 俄罗斯方块、打砖块 | `python build.py` 重新内联成单文件 |
| `vite` | 推箱子、塔防、坦克 | `pnpm build` / `npm run build` |

### 背景渐变的处理原则

6 个游戏用 `radial-gradient` 做背景层次，**只统一最深那一档**（`#0a0d16`），
亮端保留各自的色调：

| 游戏 | 亮端 | 中间 | 最深 |
| --- | --- | --- | --- |
| 贪吃蛇 | `#16224a` | `#0a0f1e` | `#0a0d16` |
| 俄罗斯方块 | `#2a1d5c` 紫 | `#170f3a` | `#0a0d16` |
| 打砖块 | `#111c33` | `#070a14` | `#0a0d16` |

为什么不一刀切：全改成同一个渐变，7 个游戏就失去辨识度了。统一的是
「最暗处」，玩家视线落在内容区时感受到的是同一套底色，而各游戏的
色调气质还在。

## 验收：用工具量，不靠肉眼

```bash
# 本地起服务 + 无头浏览器
cd 3D游戏聚合平台
node scripts/build.mjs
PORT=8099 node server/index.mjs &
chrome --headless=new --remote-debugging-port=9333   --user-data-dir=.agents/work/cp --window-size=1440,900 about:blank &

node .agents/work/tools/check-design.mjs http://127.0.0.1:8099
```

判据：**11 个维度的值在 7 个游戏间全同**才算统一。工具读的是
`getComputedStyle` 的实际渲染值，不是源码文本——源码写了
`var(--font-sans)` 不代表浏览器真用上了。

其中两个维度是硬门槛：

- **按钮圆角取值集合**：统一后每个游戏只应出现 8px / 12px / 999px
- **禁用文案**：出现「重新开始」「恢复游戏」「进入游戏」即为不合格

## 落地方式

| 层 | 谁负责 | 内容 |
| --- | --- | --- |
| 平台门户 | 平台仓库 | 已按本规范实现，是基准样板 |
| 平台注入层 | 平台仓库 | 返回按钮、共享样式表 `design-tokens.css` |
| 各游戏 | 各自仓库 | 换成规范里的字体/圆角/文案/键位 |

平台的 `portal/design-tokens.css` 是**唯一可执行副本**，各游戏从它复制
对应段落，不各自发明数值。改令牌先改这份，再同步到 7 个游戏。

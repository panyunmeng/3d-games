# 玩法硬约束（改规则前必读）

这些不是风格偏好，是「改了就会坏」的事实。每条都对应一个具体的失效场景。

## 1. 逻辑层必须保持纯净

`src/logic.js` 只能 import `src/config.js`。不得 import three、不得访问 `window`/`document`、
不得用 `performance.now()`（时间由调用方传入毫秒）。

失效场景：一旦逻辑里出现 `new THREE.Vector3`，`node --test` 直接跑不起来，BFS 机器人模拟
（tests/simulation.test.mjs）也随之失效，等于放弃了唯一能覆盖长局的回归测试。

## 2. 三个时钟不许合并

- **渲染帧**：`requestAnimationFrame` 的 dt，只驱动动画/插值。
- **逻辑 tick**：累加器 `accumulator += dt`，满 `tickMs(state)` 走一格。
- **计时钟**：`updateTimers(state, dtMs)` 按真实毫秒推进道具与关卡倒计时。

失效场景：把 t 直接乘进移动距离（连续移动），会让「直冲墙壁」这种判定取决于帧率；
把倒计时塞进 tick，会让加速道具顺带把关卡时间也加速。

## 3. 方向输入必须经过相机投影

`screenDirToGrid()` 先把按键换算成「屏幕上方/右方」的世界向量，再量化到主导轴。
不允许把 `ArrowUp` 直接映射成 `{x:0,y:-1}`。

失效场景：玩家把视角转了 90° 之后，按上会往右走。

## 4. 碰撞与生成的顺序不可乱

`tick()` 内部顺序固定为：取队列方向 → 边界(死/回绕) → 障碍 → 自身(尾格豁免) → 提交身体 →
吃食物/道具 → 关卡达标 → 无尽长障碍。

失效场景：先提交身体再判自身碰撞，会让「吃掉食物那一 tick 身体多一格」被误判成自撞；
尾格不豁免会让正常追尾必死（尾格这一 tick 会腾空，是经典贪吃蛇的正确行为）。

## 5. 生成器的三条硬规则

1. 食物/道具/障碍互不重叠，也不落在蛇身上（`blockedSet` 统一处理）。
2. 新障碍与蛇头的切比雪夫距离必须 > 2。
3. 取空位先随机采样 400 次，失败必须退化成顺序扫描，返回 null 只在棋盘真满时发生。

失效场景：障碍刷在蛇头前一格 = 玩家没有反应时间，属于不讲理而不是难度；
纯随机会在长蛇高障碍密度时长时间找不到格子，表现为卡帧。

## 6. 数值只能在 config.js

`src/logic.js`、`src/view.js`、`src/main.js` 里不允许出现新的手感常数（速度、时长、分数、尺寸）。
改完 config 必须重跑 `node --test tests/*.test.mjs`，因为部分断言直接引用 config 的常量。

## 7. 穿墙的插值必须吸附

渲染层对 `|Δx| > 1.4` 或 `|Δz| > 1.4` 的身体段直接取 t=1。

失效场景：不吸附时，从最左格瞬移到最右格会被插值成一条横穿整张棋盘的残影。

## 8. 起步必须留反应时间

出生点在倒数第 6 行（`ROWS - 6`）+ `accumulator = -900` 的起步缓冲。

失效场景：正中心出生朝上只有 10 格 ≈ 1.7 秒，低于真人「看见→判断→按键」的实际耗时，
第一局几乎必死，这是实测出来的（2026-11-17 首次试玩）。
